The first AI Factory design decision happens before the first GPU is selected.

What must the factory actually deliver?

A shared enterprise AI platform. A neocloud inference service. A portfolio of research and model-development workloads. Each ambition must become a concrete set of requirements before an architect can design the infrastructure.

For consultants, that translation is difficult. Employee counts, model sizes and vendor configurations each tell only part of the story. Peak demand, model calls, memory, placement, storage and network traffic must fit together.

We’re introducing Anubis, the open-source workload-sizing component of the Neon AI Factory Architect suite.

Anubis helps consultants move from an application description to a reviewable AI Factory design brief:

• Describe the application and distinguish what runs inside and outside the factory.
• Compare estimated B300, B200 and H200 GPU requirements.
• Review memory, host and storage requirements, alongside GPU interconnect, application traffic, customer connectivity and dedicated storage networking.
• See which assumptions support the estimate and which measurements are still needed.
• Prepare design inputs for Neon AI Factory Architect, then save the engagement for future review.

The sizing engine is deterministic. An optional, human-reviewed Copilot helps interpret workload descriptions and explain results. The calculations remain governed by explicit engineering rules.

Anubis 0.0.1 is now available for Apple Silicon Macs running macOS 13 or later. Start with the desktop installer and follow a screenshotted customer playbook from workload description to GPU estimates and a saved design handoff.

Explore 16 worked scenarios, the published methodology and the source code. The manual workflow needs no LLM account or GPU hardware.
