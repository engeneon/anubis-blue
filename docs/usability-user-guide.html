Anubis application sizing guide

Use Anubis to turn an application description into GPU and supporting-resource requirements for your downstream AI Factory design tool or process. Begin with your application architecture, enter its scale, and refine the estimate when better measurements become available.

New Engagement → Choose application → Confirm arrangement → Describe scale → Review and estimate → Design handoff

Get your access token and sign in

  1. In Finder choose Go → Go to Folder. Enter /Users/trai/Code/anubis/.anubis/.
  2. Open identities.json in a text editor. Find the entry with id equal to local-owner.
  3. Copy only its token value, without quotation marks. Do not share or screenshot it.
  4. Open Anubis, paste the value into Access token and select Open workspace.

If the file is missing, start Anubis with its local launcher. On a shared installation, ask the administrator for your own token.

Before you begin

Have the application owner describe the jobs performed, busy-period request volumes or batch deadlines, intended model and retained data. Estimates are acceptable. You do not need to know internal calculation stages or GPU cache settings to start.

Worked example for a supported application

Alder Contact Services classifies 6,000 messages in its busiest hour. Select Direct model service, enter 100 peak requests per minute and one call per request. For this initial estimate, accept the dense8b model and the displayed 2,000 input / 500 output token presets. These model and token choices are planning assumptions to replace with representative samples. Keep local compute and one organisation. Enter the five-second response objective under Optional service target. Leave storage blank until measured. Calculate to compare B300, B200 and H200 workload requirements and the separate factory deployment anchor.

When the application is outside the library

Quartz Industrial Research runs fluid simulation. Select Other GPU application and name the component Fluid simulation. Record the solver, mesh, steps, memory and deadline in Customer context and measurement notes. Anubis retains this requirement and exports a brief. It does not reinterpret fluid simulation as a language-model workload or report zero GPUs as a valid estimate. Supply a solver-specific reference capacity using the reference-sizing form before a GPU recommendation can be made. The separate incomplete-assessment action remains available when measurements are not yet obtainable.

Check GPU sizing readiness before calculation

The orange GPU estimate blocked panel names the exact inputs still required. Select a field in the panel to open it. The panel updates as you type. Calculate estimate is disabled until the minimum inputs are present. Then review and accept the assumptions. Input readiness is not a performance guarantee or a memory-feasibility result.

Text serving needs a local model or accepted preset, peak requests per minute (or active users and their request interval), model calls per request and input/output tokens. Batch work needs jobs and the completion window. Training needs token count and deadline. Presets may supply explicitly reviewed model and token assumptions. Employee counts and daily totals do not silently become peak demand.

Size a specialist application with reference capacity

Select the activity in the diagram. In Describe scale, choose Reference capacity for independent work. Enter the work unit, peak units per second, GPUs per complete group, required GB per GPU and a separate capacity for H200, B200 and B300. Identify the source and matching model or solver configuration. Confirm that independent groups can serve the demand and accept the reference scope. For local retrieval, confirm that the reference includes its resources.

The calculation replicates complete groups and rounds to whole eight-GPU nodes. It does not infer how one larger distributed job scales or extrapolate between hardware platforms. A fictional demonstration reference is a planning assumption, not benchmark evidence. Copilot preserves manually supplied reference data and requires renewed consultant acceptance after refinement.

What Prepare projection transfers

Download the design intake, readable architecture brief and companion specification together. The intake maps E-W fabric and storage technology. It does not automatically populate N-S bandwidth, external customer-datacenter connectivity or dedicated-storage separation and throughput. Those requirements remain in the brief and companion for the architect to apply. Ethernet technology alone does not enforce a physically dedicated fabric.

Factory networks

In Describe scale, open Factory networks and customer datacenter connection. Enter the initial dataset volume in TB and loading window in hours. Initial loading always crosses the external customer-datacenter connection. Enter ongoing bulk transfers separately from model traffic. State whether initial loading overlaps normal operation.

Results distinguish external connectivity, north-south traffic, a physically dedicated storage network and east-west GPU communication. No converged storage network is assumed. Unknown storage or GPU communication rates remain requests for measurements. The readable brief and companion export retain all four roles even when the downstream intake has no matching field.

The default usable link fraction is 70%. The protocol allowance comes from the accepted planning profile. Both are editable assumptions. Calculated rates are lower bounds, not selected commercial circuit speeds.

Appendix — interpreting estimates

Model profiles, serving efficiencies and host provisions are explicit planning assumptions. Sensitivity envelopes are not confidence intervals. A response-time objective is retained for validation, not certified by analytical throughput. Blank data capacity or throughput is unspecified. Local retrieval and indexing remain separate requirements until measured. GPU subtotals exclude unsupported components. External token traffic is a floor for declared application traffic, not a complete WAN design. Reference-architecture anchors describe deployment options, not evidence of workload throughput. Final configuration and service performance require the architect's review.

Explain this to me

From calculation results or Design handoff, choose Explain this to me. Select a tested model connection or the deterministic option, confirm the appropriate data classification and select Generate explanation. The status indicator shows ongoing work. Read the saved-result narrative, inspect its source fields and download it. Reopen the panel to retrieve earlier explanations of the same calculation. Model prose cannot change the saved workload, GPU counts or handoff. Invalid or unavailable model responses use a clearly labelled deterministic fallback. Change assumptions through the workload builder and calculate again.
