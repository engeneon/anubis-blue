Anubis playbook standard

1. Introduce the customer scenario and intended outcome in plain language.
2. Immediately after the scenario introduction, present the workflow input register. No operational steps should intervene. Use columns for reference ID, exact UI field, plain-language definition and scope, exact value or action, and basis. Include selected defaults, explicit entries and unresolved values. Distinguish active inputs from outputs. Never include access credentials.
3. Include access-token instructions, a conceptual system diagram and numbered click-by-click instructions with activity text and screenshots.
4. Include a tabular parameter collection appendix covering every register ID. Required columns are ID, exact UI parameter, definition and scope, how to obtain or decide it, and what to do when unknown. Explain the source or responsible decision-maker, measurement method, units and useful scripts, metrics or tools. Use tables every time, not a sequence of prose parameter headings. Link applicable official tutorials where useful.
5. Derive the register and appendix from the same parameter dataset. Validate complete coverage and document order on each build.
6. Preserve uncertainty and source provenance. A default is not a measurement. A blank is not zero. Separate business targets from observed performance.
7. Cover all four network roles and distinguish mapped intake fields from requirements retained in the companion brief.
8. Use downstream AI Factory design tool or process in customer narrative. Do not use semicolons as sentence separators.
9. Render the Word and PDF editions and inspect every page before delivery. Keep screenshot instructions and input values consistent.

10. Include the shared placement glossary in the appendix. Prefer Outside this AI Factory over a bare external label. Explain whether the label refers to compute, retrieval, document storage or connectivity. Give concrete system-class examples and distinguish source-corpus capacity from index size and local copies.

11. Use the shared deliverables/usability/playbook_typography.py formatter on every playbook build. Field labels use the Anubis UI Field character style (Arial, bold, dark blue #17365D). Literal values use Anubis UI Value (Courier New, dark green #185B45). Buttons and expandable controls use Anubis UI Control (bold dark blue, in square brackets). States such as blank or unchecked use Anubis UI State (bold italic dark green). Explanations remain normal body text. Do not rely on colour alone. Include the reader key before the scenario. Apply field/value styles to the input register as well as instructions.
12. Author new instructions with explicit semantic spans: [[field:Factory users]] = [[value:One organisation]]. Click [[control:Continue]]. Leave [[field:Reserve dedicated capacity 1]] [[state:unchecked]]. Use exact UI wording. The shared formatter supports legacy phrases, but new labels and values must be explicitly annotated. Keep reasons and qualifications outside styled spans. Separate instruction groups into paragraphs. Never expose markup in delivered documents. Run tests/test_playbook_typography.py and the delivery validator, then render and inspect the result.

13. Explain material scope statements at first use. For example, explain that no requested corpus copy means outside corpus capacity is not automatically local retained storage or an initial transfer volume.
14. Define application components as business activities, not physical hardware. Explain numbered labels and give an example of multiple activities with different compute locations. Distinguish compute location from search location.
15. Define time and storage boundaries explicitly. State whether a response metric is TTFT or complete-response time, its percentile and excluded phases. Distinguish factory-retained shared data, GPU-server local disks, source corpus, search index and copies. Describe current application behaviour rather than implying unsupported storage choices.
16. Each step must be executable without decoding a register ID. Repeat the exact field label and literal text to enter at the step. IDs are traceability aids only. Do not use instructions such as "copy I29 text" or "copy I38" without reproducing the text.
17. Generate register definitions and appendix definitions from one shared source. Validate every ID occurs in both tables, all definitions and collection methods are present, and literal text repeated in steps matches the register. Preserve annotated user originals. Retain a comment-resolution record for reviewed changes.
